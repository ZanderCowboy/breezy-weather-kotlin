Data Flow Journey

Let's follow a typical user action: "User opens app and wants to see current weather"

1. UI Layer

MainActivity starts and calls MainActivityViewModel

📱 User Action: App opens → MainActivity.onCreate() → Creates ViewModel

2. ViewModel Layer

MainActivityViewModel requests weather data from WeatherRepository

🧠 State Management: ViewModel.getWeather() → Calls repository with location

3. Repository Layer

WeatherRepository checks database first, then calls external WeatherService

💾 Data Access: Repository.getWeather() → Database check → Service call if needed

4. Service Layer

OpenWeatherService (or other) makes HTTP call to weather API

☁️ External API: Service.getCurrentWeather() → HTTP request → JSON response

5. Mapper Layer

WeatherMapper transforms JSON response into domain models

🔄 Data Transformation: WeatherMapper.mapWeather() → JSON → Weather data class

6. Back to UI

Data flows back: Repository → ViewModel → UI updates with weather info

📱 UI Update: Weather data → ViewModel state → UI recomposition → User sees weather!

Key Classes & Their Roles

MainActivity

Activity

Role: Main UI entry point, manages fragments and navigation

Dependencies:

  • → MainActivityViewModel (state management)
  • → SourceManager (weather sources)
  • → LocationRepository (location data)
  • → HomeFragment & ManagementFragment

Kotlin Features: @AndroidEntryPoint, lateinit var, companion object

MainActivityViewModel

ViewModel

Role: Manages UI state and coordinates data operations

Dependencies:

  • → WeatherRepository (weather data)
  • → LocationRepository (location data)
  • → SettingsRepository (app settings)
  • Uses coroutines and Flow for async operations

Kotlin Features: suspend functions, Flow, StateFlow, @Inject

WeatherRepository

Repository

Role: Abstracts weather data access (database + network)

Dependencies:

  • → DatabaseHandler (local storage)
  • → WeatherMapper (data transformation)
  • Stores Weather, Daily, Hourly, Minutely, Alert data

Kotlin Features: suspend functions, generics, default parameters

WeatherMapper

Object

Role: Transforms database rows into domain models

Functions:

  • mapWeather() - Creates Weather data class
  • mapDaily() - Creates Daily forecast objects
  • mapHourly() - Creates Hourly forecast objects
  • mapAlert() - Creates Alert objects

Kotlin Features: object keyword, nullable types, Date conversion

OpenWeatherService

Service

Role: Fetches weather data from OpenWeatherMap API

Implements:

  • WeatherSource interface
  • LocationSearchSource interface
  • ReverseGeocodingSource interface
  • Uses Retrofit for HTTP calls

Kotlin Features: interfaces, suspend functions, data classes

DatabaseHandler

Interface

Role: Abstracts database operations with clean API

Functions:

  • await<T>() - Generic async database operations
  • awaitList<T>() - List queries with generics
  • subscribeToList() - Reactive Flow streams
  • subscribeToOne() - Single item streams

Kotlin Features: interfaces, generics, suspend functions, Flow

Weather

Data Class

Role: Core weather data model containing all weather information

Properties:

  • base: Base (timestamps and metadata)
  • current: Current? (current weather conditions)
  • dailyForecast: List<Daily>
  • hourlyForecast: List<Hourly>
  • alertList: List<Alert>

Kotlin Features: data class, nullable types, collections

WeatherCode

Enum Class

Role: Type-safe weather condition constants

Values:

  • CLEAR, PARTLY_CLOUDY, CLOUDY
  • RAIN, SNOW, SLEET, HAIL
  • THUNDERSTORM, FOG, WIND
  • Companion object with utility functions

Kotlin Features: enum class, companion object, when expressions

Dependency Injection Flow

BreezyWeather uses Hilt for dependency injection. Here's how dependencies flow through the app:

@HiltAndroidApp

BreezyWeather (Application class) enables Hilt for the entire app

🏗️ Setup: @HiltAndroidApp generates dependency injection code

@AndroidEntryPoint

MainActivity can now receive injected dependencies

🔌 Injection Ready: Activities, Fragments, ViewModels can use @Inject

@Inject Constructor

Repositories & Services get their dependencies automatically

💉 Auto-Wiring: Hilt provides DatabaseHandler, HTTP clients, etc.

Dependency Chain Example:

// MainActivity gets injected ViewModel
@AndroidEntryPoint
class MainActivity {
    private lateinit var viewModel: MainActivityViewModel
}

// ViewModel gets injected Repository
class MainActivityViewModel @Inject constructor(
    private val weatherRepository: WeatherRepository
)

// Repository gets injected DatabaseHandler
class WeatherRepository(
    private val handler: DatabaseHandler
)

Real-World Example: Getting Weather

Let's trace through the exact code path when a user refreshes weather data:

🎯 Step-by-Step Code Flow:

1️⃣ UI Action (MainActivity.kt)
// User pulls to refresh
swipeRefresh.setOnRefreshListener {
    viewModel.refreshWeather()
}
2️⃣ ViewModel Coordination (MainActivityViewModel.kt)
fun refreshWeather() {
    viewModelScope.launch { // Coroutine scope
        _isLoading.value = true
        try {
            val weather = weatherRepository.getWeatherByLocationId(locationId)
            _weatherData.value = weather
        } catch (e: Exception) {
            _error.value = e.message
        } finally {
            _isLoading.value = false
        }
    }
}
3️⃣ Repository Logic (WeatherRepository.kt)
suspend fun getWeatherByLocationId(locationId: String): Weather? {
    // Get from database using mapper
    val weather = handler.awaitOneOrNull {
        weathersQueries.getWeatherByLocationId(locationId, WeatherMapper::mapWeather)
    }
    
    // Add related data (daily, hourly, alerts)
    return weather?.copy(
        dailyForecast = getDailyListByLocationId(locationId),
        hourlyForecast = getHourlyListByLocationId(locationId),
        alertList = getAlertListByLocationId(locationId)
    )
}
4️⃣ Data Mapping (WeatherMapper.kt)
object WeatherMapper {
    fun mapWeather(
        refreshTime: Long?,
        temperature: Double?,
        weatherCode: WeatherCode?,
        // ... many more parameters
    ): Weather = Weather(
        base = Base(refreshTime?.let { Date(it) }),
        current = Current(
            temperature = Temperature(temperature),
            weatherCode = weatherCode
        )
    )
}
5️⃣ UI Update (MainActivity.kt)
// Observe ViewModel state changes
viewModel.weatherData.observe(this) { weather ->
    weather?.let {
        updateWeatherDisplay(it) // Update UI elements
        swipeRefresh.isRefreshing = false
    }
}

Architecture Benefits

Separation of Concerns

  • UI only handles display logic
  • ViewModels manage state and business logic
  • Repositories handle data access
  • Services handle external communication
  • Mappers handle data transformation

Testability

  • Interfaces allow easy mocking
  • Repository pattern abstracts data sources
  • ViewModels can be tested independently
  • Dependency injection enables test doubles
  • Pure functions in mappers are easily testable

Flexibility

  • Easy to swap weather service implementations
  • Database can be changed without affecting UI
  • Multiple UI implementations possible
  • Configuration changes handled gracefully
  • Modular architecture supports feature flags

Performance

  • Coroutines prevent UI blocking
  • Flow provides reactive data updates
  • Repository caches data efficiently
  • Lazy loading of related data
  • Background processing with WorkManager
