What are Data Classes?

Data classes are Kotlin's superpower for creating simple classes that primarily hold data. Think of them as smart containers that automatically generate useful methods for you! 📦

Core Concept: Smart Data Containers

Discover why data classes are better than regular classes for holding data

Data Class Magic: C.E.T.H

Copy function - clone with modifications

Equals - smart object comparison

ToString - pretty string representation

HashCode - for use in collections (HashMap, HashSet)

⚖️ Data Class vs Regular Class

Regular Class (Java-style)

class Person(
    val name: String,
    val age: Int
) {
    // Must manually implement:
    override fun equals(other: Any?): Boolean
    override fun hashCode(): Int
    override fun toString(): String
    // copy() function? Write it yourself!
}

😰 Lots of boilerplate code!

Data Class (Kotlin-style)

data class Person(
    val name: String,
    val age: Int
)

// That's it! Kotlin auto-generates:
// - equals() and hashCode()
// - toString()
// - copy() function
// - componentN() functions

😍 Clean and concise!

🤖 Auto-Generated Methods

📋 toString()

Provides a readable string representation

Person(name=John, age=25)

⚖️ equals() & hashCode()

Smart comparison based on property values

person1 == person2 // true if all properties match

📄 copy()

Clone object with optional modifications

val older = person.copy(age = 26)

🔢 componentN()

Destructuring support

val (name, age) = person

🎯 When to Use Data Classes

✅ Perfect for:

  • API Models: JSON response objects
  • Database Entities: Room database tables
  • Configuration Objects: Settings, preferences
  • Value Objects: Coordinates, dates, measurements
  • State Holders: UI state, form data

❌ Avoid for:

  • Complex Business Logic: Use regular classes
  • Inheritance Hierarchies: Data classes are final
  • No-parameter Classes: Must have at least one parameter
  • Mutable Heavy Classes: Consider regular classes

// From Wind.kt - Wind measurement data class
data class Wind(
    val degree: Double? = null, // Wind direction in degrees
    val speed: Double? = null, // Wind speed
    val gusts: Double? = null, // Wind gusts
) : Serializable { // Can be serialized for storage

    // 🏃‍♂️ Custom property with getter
    val isValid: Boolean
        get() = speed != null && speed > 0

    // 🧭 Wind direction arrow based on degrees
    val arrow: String?
        get() = when (degree) {
            null -> null
            -1.0 -> "⟳" // Variable wind
            in 22.5..67.5 -> "↙" // Northeast wind
            in 67.5..112.5 -> "←" // East wind
            in 112.5..157.5 -> "↖" // Southeast wind
            in 157.5..202.5 -> "↑" // South wind
            in 202.5..247.5 -> "↗" // Southwest wind
            in 247.5..292.5 -> "→" // West wind
            in 292.5..337.5 -> "↘" // Northwest wind
            else -> "↓" // North wind
        }
}

🚀 Advanced Features in Wind Data Class

  • Double? - Nullable types (can hold null values) 🤲
  • = null - Default parameter values (optional parameters)
  • : Serializable - Interface implementation for data persistence
  • get() = ... - Custom property getters for computed values
  • when (degree) - Smart switch statement with pattern matching
  • in 22.5..67.5 - Range expressions for number ranges

🤲 Null Safety: The Kotlin Way

Kotlin eliminates the billion-dollar mistake (NullPointerException) with null safety!

// Nullable vs Non-nullable types
val speed: Double = 10.5 // Cannot be null
val gusts: Double? = null // Can be null

// Safe operations
val isWindy = speed > 10 // ✅ Direct access
val hasGusts = gusts?.let { it > 15 } ?: false // ✅ Safe call

// This won't compile! Null safety at compile time
// val dangerous = gusts > 15 // ❌ Compiler error

🛡️ Null Safety Operators:

  • ?. - Safe call (returns null if receiver is null)
  • ?: - Elvis operator (default value if null)
  • !! - Not-null assertion (use carefully!)
  • ?.let { } - Execute block only if not null

🎯 When Expressions: Smart Switch

Kotlin's when is like switch on steroids! 💪

// Pattern matching with ranges
val windDescription = when (speed) {
    null -> "No data"
    in 0.0..5.0 -> "Calm" // Range check
    in 5.0..15.0 -> "Light breeze"
    in 15.0..30.0 -> "Strong breeze"
    else -> "Gale force!"
}

// Can also check types, conditions, etc.
when {
    speed == null -> "No wind data"
    speed > 50 -> "Hurricane force!"
    isValid -> "Normal wind"
    else -> "Invalid reading"
}

⚙️ Custom Property Getters

Add computed properties that calculate values on-the-fly!

// Custom getter - computed every time accessed
val isValid: Boolean
    get() = speed != null && speed > 0

// Alternative: backing field (computed once)
val isValidCached: Boolean by lazy {
    speed != null && speed > 0
}

// Usage
val wind = Wind(degree = 45.0, speed = 12.5)
println(wind.isValid) // true
println(wind.arrow) // "↙"

Benefits: Clean API, encapsulation, computed values without storing extra data!

Data Class Operations

Master Data Class Functions

Learn copy(), destructuring, and equality operations

// Creating and manipulating data classes
val originalWind = Wind(
    degree = 180.0, 
    speed = 15.0, 
    gusts = 20.0
)

// 📄 Copy with modifications
val strongerWind = originalWind.copy(speed = 25.0)
val calmWind = originalWind.copy(speed = 0.0, gusts = null)

// 🔢 Destructuring assignment
val (direction, windSpeed, gustSpeed) = originalWind
println("Wind: ${windSpeed}mph from ${direction}°")

// ⚖️ Equality comparison (by values, not reference)
val sameWind = Wind(180.0, 15.0, 20.0)
println(originalWind == sameWind) // true - same values
println(originalWind === sameWind) // false - different objects

// 📋 String representation
println(originalWind) // Wind(degree=180.0, speed=15.0, gusts=20.0)

// 🗂️ Use in collections
val windReadings = setOf(originalWind, sameWind, strongerWind)
println(windReadings.size) // 2 (originalWind == sameWind)

Pro Tips:

  • copy(): Creates a shallow copy - perfect for immutable updates
  • Destructuring: Only works with first few properties (component functions)
  • Equality: Based on property values, great for testing and collections
  • toString(): Automatic debugging-friendly representation
