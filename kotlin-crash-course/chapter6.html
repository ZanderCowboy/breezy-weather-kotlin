Coroutines: Async Made Easy

Master Kotlin Coroutines

Learn async programming that doesn't block your UI

⚡ What are Coroutines?

Coroutines are like lightweight threads that don't block your UI. Think of them as "pausable functions" that can suspend and resume without freezing your app!

❌ Traditional Threading

// Blocking UI thread - BAD!
fun loadWeather() {
    val data = networkCall() // UI freezes! 😱
    updateUI(data)
}
  • UI freezes during network calls
  • Complex callback hell
  • Hard to handle errors
  • Memory leaks with threads

✅ Coroutines

// Non-blocking - AWESOME!
suspend fun loadWeather() {
    val data = networkCall() // Suspends, doesn't block! ✨
    updateUI(data)
}
  • UI stays responsive
  • Sequential-looking code
  • Built-in error handling
  • Automatic lifecycle management

⏸️ Suspend Functions

Suspend functions are the building blocks of coroutines. They can pause execution without blocking threads!

// Suspend function for network calls
suspend fun fetchWeatherData(location: Location): WeatherData {
    // This suspends (pauses) instead of blocking
    return weatherApi.getCurrentWeather(location)
}

// Suspend function for database operations
suspend fun saveWeatherData(data: WeatherData) {
    // Database operations can also suspend
    database.insert(data)
}

// Combining suspend functions
suspend fun refreshWeather(location: Location) {
    try {
        val data = fetchWeatherData(location) // Suspend point 1
        saveWeatherData(data)                  // Suspend point 2
        notifyUI(data)
    } catch (e: Exception) {
        handleError(e)
    }
}

🎯 Key Point: Suspend functions can only be called from other suspend functions or from coroutines!

🌦️ Real Weather App Examples

// In a ViewModel
class WeatherViewModel : ViewModel() {
    
    fun refreshWeather() {
        viewModelScope.launch { // Launch coroutine
            _isLoading.value = true
            
            try {
                // Multiple async operations
                val current = async { getCurrentWeather() }
                val forecast = async { getForecast() }
                
                // Wait for both to complete
                _weatherData.value = WeatherState(
                    current = current.await(),
                    forecast = forecast.await()
                )
            } catch (e: Exception) {
                _error.value = e.message
            } finally {
                _isLoading.value = false
            }
        }
    }
}

Flow: Reactive Data Streams

Master Kotlin Flow

Learn reactive programming for real-time UI updates

// Flow for observing weather data changes
class WeatherRepository {
    
    // 🌊 Flow emits values over time
    fun observeWeatherUpdates(): Flow<WeatherData> = flow {
        while (true) {
            val latest = fetchLatestWeather()
            emit(latest) // Emit new data
            delay(60_000) // Wait 1 minute
        }
    }
    
    // 🔄 Transform data with operators
    fun getTemperatureUpdates(): Flow<String> = 
        observeWeatherUpdates()
            .map { "${it.temperature}°C" }        // Transform data
            .distinctUntilChanged()             // Only emit if changed
            .flowOn(Dispatchers.IO)             // Run on background thread
}

// In UI
class WeatherActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        
        // 📱 Collect flow in UI
        lifecycleScope.launch {
            repository.getTemperatureUpdates()
                .collect { temperature ->
                    temperatureText.text = temperature // Auto-updates UI!
                }
        }
    }
}

Flow Operators

  • map: Transform each value
  • filter: Only emit values that match condition
  • distinctUntilChanged: Skip duplicate consecutive values
  • debounce: Wait for pause in emissions
  • combine: Combine multiple flows
  • catch: Handle errors gracefully

Sealed Classes: Type-Safe States

Master Sealed Classes

Perfect for representing states and results

// Sealed class for UI states - perfect for weather app!
sealed class WeatherUiState {
    object Loading : WeatherUiState()
    
    data class Success(
        val weather: WeatherData,
        val lastUpdated: Date
    ) : WeatherUiState()
    
    data class Error(
        val message: String,
        val canRetry: Boolean = true
    ) : WeatherUiState()
    
    object Empty : WeatherUiState()
}

// Exhaustive when expression - compiler ensures all cases handled!
fun updateUI(state: WeatherUiState) {
    when (state) {
        is WeatherUiState.Loading -> {
            progressBar.isVisible = true
            errorLayout.isVisible = false
        }
        is WeatherUiState.Success -> {
            progressBar.isVisible = false
            displayWeather(state.weather)
            lastUpdatedText.text = "Updated: ${state.lastUpdated}"
        }
        is WeatherUiState.Error -> {
            progressBar.isVisible = false
            errorText.text = state.message
            retryButton.isVisible = state.canRetry
        }
        is WeatherUiState.Empty -> {
            showEmptyState()
        }
        // No else needed - compiler knows all cases are covered! 🛡️
    }
}

🎯 Sealed Class Benefits:

  • Type Safety: Compiler ensures exhaustive when expressions
  • Clear States: All possible states are explicitly defined
  • Data Classes: Can carry associated data with each state
  • Refactoring: Adding new states causes compile errors until handled
  • No Null: Better than nullable booleans for state management

Higher-Order Functions

Functions as Parameters

Pass functions as arguments for flexible APIs

// Higher-order functions in weather app
fun List<WeatherData>.filterByCondition(
    predicate: (WeatherData) -> Boolean  // Function parameter!
): List<WeatherData> = this.filter(predicate)

// Usage examples
val sunnyDays = weatherHistory.filterByCondition { it.isSunny() }
val hotDays = weatherHistory.filterByCondition { it.temperature > 30 }
val recentDays = weatherHistory.filterByCondition { 
    it.date.isAfter(Date().minusDays(7)) 
}

// Function that returns a function!
fun createTemperatureFilter(minTemp: Double): (WeatherData) -> Boolean {
    return { weather -> weather.temperature >= minTemp }
}

val warmDayFilter = createTemperatureFilter(20.0)
val warmDays = weatherHistory.filterByCondition(warmDayFilter)

// Kotlin collection functions are higher-order functions!
val temperatures = weatherData
    .map { it.temperature }              // Transform each item
    .filter { it > 0 }                  // Keep only positive
    .sortedDescending()                  // Sort high to low
    .take(5)                           // Take first 5

Scope Functions

Master let, run, with, also, apply

Kotlin's scope functions for cleaner code

// Scope functions in weather app

// 🔧 apply - configure object and return it
val weatherView = WeatherCardView(context).apply {
    setTemperature(25.0)
    setCondition("Sunny")
    setLocation("New York")
    isVisible = true
}

// 📋 let - transform non-null values
weatherData?.let { data ->
    updateTemperature(data.temperature)
    updateHumidity(data.humidity)
    updateWindSpeed(data.windSpeed)
}

// 🔄 run - execute block and return result
val temperatureText = weatherData?.run {
    when {
        temperature > 30 -> "Hot: ${temperature}°C"
        temperature > 20 -> "Warm: ${temperature}°C"
        temperature > 0 -> "Cool: ${temperature}°C"
        else -> "Cold: ${temperature}°C"
    }
}

// 🏃‍♂️ with - operate on object without null check
with(binding.weatherCard) {
    temperatureText.text = "${weather.temperature}°"
    conditionText.text = weather.condition
    humidityText.text = "${weather.humidity}%"
    isVisible = true
}

// ➕ also - perform side effects and return original
val savedWeather = weather
    .also { println("Saving weather: $it") }
    .also { database.save(it) }
    .also { notifyObservers(it) }

🧠 Scope Function Cheat Sheet:

  • apply: Configure object, return object (this)
  • let: Transform object, return result (it)
  • run: Execute code block, return result (this)
  • with: Operate on object, return result (this)
  • also: Side effects, return original object (it)
