What are Enum Classes?

Enum classes represent a fixed set of constants in a type-safe way. Think of them as a group of related constants that belong together, like weather conditions, days of the week, or user roles! 🏷️

Core Concept: Type-Safe Constants

Discover why enums are better than plain constants

Enum Class Benefits: S.A.F.E

Structured constants - organized and grouped

Auto-complete friendly - IDE helps you

Fixed set of values - no invalid states

Easy pattern matching - works great with when

🆚 Enum vs Plain Constants

❌ Plain Constants (Bad)

const val CLEAR = "clear"
const val CLOUDY = "cloudy"
const val RAIN = "rain"

// Problems:
fun getIcon(weather: String) {
    // Can pass ANY string!
    // "sunny", "cloudy", "raining"
    // No type safety 😰
}
  • No type safety
  • Can pass wrong values
  • Hard to maintain
  • No IDE assistance

✅ Enum Class (Good)

enum class WeatherCode {
    CLEAR, CLOUDY, RAIN
}

// Type-safe function
fun getIcon(weather: WeatherCode) {
    // Only valid weather codes!
    // Compiler enforces this ✅
}
  • Complete type safety
  • Only valid values allowed
  • Easy refactoring
  • Great IDE support

🌟 Powerful Enum Features

🎨 Enums Can Have:

  • Properties: Store additional data with each constant
  • Methods: Define behavior for enum values
  • Constructors: Initialize properties
  • Companion Objects: Static utility functions
  • Interface Implementation: Shared behavior
// Rich enum with properties and methods
enum class WeatherCode(val icon: String, val severity: Int) {
    CLEAR("☀️", 1),
    CLOUDY("☁️", 2),
    RAIN("🌧️", 4);
    
    fun isSevere() = severity > 3
}

🎯 Perfect with When Expressions

Enums and when are a match made in heaven! The compiler ensures you handle all cases.

// Exhaustive when expressions
fun getDescription(weather: WeatherCode): String = when (weather) {
    WeatherCode.CLEAR -> "Beautiful sunny day!"
    WeatherCode.CLOUDY -> "Overcast skies"
    WeatherCode.RAIN -> "Bring an umbrella!"
    // Compiler error if you miss a case! 🛡️
}

// Works great with sealed when
val recommendation = when (weather) {
    WeatherCode.CLEAR, WeatherCode.CLOUDY -> "Great for outdoor activities"
    WeatherCode.RAIN -> "Stay indoors or bring rain gear"
}

🛡️ Exhaustive Check: The compiler ensures you handle all enum values. Add a new enum constant? Compiler will tell you where to update your when expressions!

// From WeatherCode.kt - Main weather condition enum
enum class WeatherCode(val id: String) {
    CLEAR("clear"),                    // ☀️ Sunny weather
    PARTLY_CLOUDY("partly_cloudy"),    // ⛅ Partly cloudy
    CLOUDY("cloudy"),                // ☁️ Overcast
    RAIN("rain"),                    // 🌧️ Rainy weather
    SNOW("snow"),                    // ❄️ Snow
    SLEET("sleet"),                  // 🌨️ Mixed precipitation
    HAIL("hail"),                    // 🧊 Hailstorm
    FOG("fog"),                      // 🌫️ Foggy conditions
    WIND("wind"),                    // 💨 Windy weather
    THUNDERSTORM("thunderstorm");    // ⛈️ Thunderstorm

    // 🔧 Companion object for utility functions
    companion object {
        // 🔍 Find enum by string value (null-safe)
        fun getInstance(value: String?): WeatherCode? = 
            WeatherCode.entries.firstOrNull { // New Kotlin way (.entries)
                it.id.equals(value, ignoreCase = true)
            }
    }
}

// Usage examples
val currentWeather = WeatherCode.getInstance("rain") // Returns RAIN
val invalidWeather = WeatherCode.getInstance("sunny") // Returns null

🔍 Code Breakdown

  • enum class WeatherCode(val id: String) - Enum with constructor parameter
  • CLEAR("clear") - Each enum constant gets an id property
  • companion object - Static utility functions for the enum
  • .entries - Modern way to get all enum values (replaces .values())
  • firstOrNull { } - Safely find matching enum or return null
  • ignoreCase = true - Case-insensitive string matching

💡 Pro Tip: Always use companion object functions for string-to-enum conversion to handle invalid inputs gracefully!

👥 Companion Object Deep Dive

Companion objects provide static-like functionality to enums:

companion object {
    // 🔍 Safe string conversion
    fun getInstance(value: String?): WeatherCode? = 
        WeatherCode.entries.firstOrNull {
            it.id.equals(value, ignoreCase = true)
        }
    
    // 🌧️ Get all precipitation types
    fun getPrecipitationTypes(): List<WeatherCode> = 
        listOf(RAIN, SNOW, SLEET, HAIL)
    
    // ⚠️ Get severe weather conditions
    fun getSevereWeather(): List<WeatherCode> = 
        listOf(THUNDERSTORM, HAIL, WIND)
}

Benefits: Centralized logic, easy to test, clean API!

📚 Working with Enum Collections

Enums work perfectly with Kotlin collections:

// Get all enum values
val allWeatherTypes = WeatherCode.entries // Modern way
val allWeatherTypesOld = WeatherCode.values() // Legacy way

// Filter and map operations
val precipitationIds = WeatherCode.entries
    .filter { it in listOf(WeatherCode.RAIN, WeatherCode.SNOW) }
    .map { it.id }

// Use in sets for fast lookup
val severeWeather = setOf(
    WeatherCode.THUNDERSTORM, 
    WeatherCode.HAIL
)

fun isWeatherSevere(weather: WeatherCode) = 
    weather in severeWeather // O(1) lookup!
